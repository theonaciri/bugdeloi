# Notes — C0.2 reproduction n° 2 sur les XML DILA bruts (`replications/c0.2-dila-xml`)

Constats faits en lisant directement les archives LEGI (stock du 08/11/2026 et incréments au 24/11/2026),
sans le code d'ingestion. Rapport : [`replications/c0.2-dila-xml/REPORT.md`](../../replications/c0.2-dila-xml/REPORT.md).

## Structure réelle des archives

- Le stock `Freemium_legi_global_*.tar.gz` commence par `legi/global/…`. Les incréments `LEGI_<horodatage>.tar.gz`
  préfixent tout par `<horodatage>/` (`20261124-221545/legi/global/…`) et portent à leur racine
  `liste_suppression_legi.dat` et `liste_suppression_legi_dossier.dat`. Certains incréments n'ont **aucune**
  liste de suppression : `tar --wildcards '*/liste_suppression_legi.dat'` échoue alors, ce n'est pas une erreur.
- Les lignes de `liste_suppression_legi.dat` sont des chemins **sans** `.xml` et sans le préfixe d'horodatage.
  Celles de `…_dossier.dat` finissent par ` D` (dossier). Aucune ne visait les trois codes sur la période.
- Articles des codes : `legi/global/code_et_TNC_en_vigueur/code_en_vigueur/LEGI/TEXT/<5 niveaux>/<LEGITEXT>/article/LEGI/ARTI/<5 niveaux>/<LEGIARTI>.xml`.
  Les 71 881 fichiers article du stock pour CGI, CSS et CCH sont tous sous `code_en_vigueur`, y compris les
  versions abrogées ou modifiées. Le nom de fichier est l'`ID` (contrôlé à la lecture : 0 écart).
- Les chemins dépassent 100 octets : le lecteur tar gère le champ `prefix` ustar,
  les en-têtes GNU `L` et pax `x` (le type utilisé n’a pas été compté).
- `gzip -dc` du stock (1,2 Go) sous `nice` : ~54 s sur l'hôte aarch64. Les incréments : < 1 s chacun.

## XML article

- `META_ARTICLE` : `NUM`, `ETAT`, `DATE_DEBUT`, `DATE_FIN`, `TYPE`, entourés de lignes vides.
  `CONTEXTE/TEXTE@cid` donne le texte.
- `VERSIONS/VERSION/LIEN_ART@{id,etat,debut,fin,num}` : les attributs coïncident exactement avec l'en-tête
  du fichier de chaque version (0 écart sur 71 884). Une lignée peut contenir des versions `MODIFIE_MORT_NE`
  dont `fin < début` : à exclure pour trouver la « dernière » version.
- Un même numéro peut porter plusieurs lignées (article abrogé puis recréé, numéro réattribué) : CCH R111-2,
  CSS D136-1, CCH R131-39, CSS D756-2.
- États rencontrés : `MODIFIE`, `VIGUEUR`, `ABROGE`, `TRANSFERE`, `MODIFIE_MORT_NE`, `ABROGE_DIFF`, `PERIME`,
  `VIGUEUR_DIFF`, `ANNULE`, `DISJOINT`, `DEPLACE` (2 versions).
- `ABROGE_DIFF` avec `DATE_FIN = 2222-02-22` : 37 versions sources de candidats. Elles restent en vigueur.
- Lignée incomplète : CGI 238 bis AA finit sur une version `MODIFIE` (1997-04-11 → 2002-01-05), suivie seulement
  d'une version mort-née ; CGI 238 bis A est dans le même cas (`MODIFIE` jusqu'au 2000-03-31). Un dernier état
  non terminal signale un trou des données, pas une fin d'article.

## Pièges

- **Mémoire (JavaScriptCore)** : les sous-chaînes extraites d'un XML le gardent en mémoire. Sans copie, garder
  quelques champs de 72 000 fichiers montait à **2,7 Gio** de pointe. Après copie forcée (`TextEncoder` puis
  `TextDecoder`), dédoublonnage des valeurs et partage des blocs `VERSIONS` identiques, la pointe tombe à
  **~500 Mio**.
- Suppressions annoncées : 24 lignes visent les trois codes, soit 20 identifiants (certains répétés plusieurs
  jours de suite). Seules 2 visent un fichier présent ; les autres visent des versions absentes du stock,
  qu'aucun bloc `VERSIONS` ne cite.
- Normaliser les guillemets ne suffit pas : « x » (avec espaces insécables) et `"x"` diffèrent encore par les
  espaces. Les retirer des deux côtés de `"` dans les deux textes rend la comparaison symétrique. Les balises
  inline (`<sup>`, etc.) ajoutent des espaces : il faut un repli sans espaces (2 extraits sur 1 112).
