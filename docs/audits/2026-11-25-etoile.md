## Méthode et commande

Le relevé parcourt les fichiers Catala lettrés du [commit Inria épinglé](https://github.com/CatalaLang/catala-examples/tree/9e251b932288cf5f4a74af072d203144a057494b).
Il retient un titre portant un identifiant LEGIARTI si un bloc fermé `catala` ou `catala-metadata`
contient une définition, une règle, une assertion ou une déclaration. Le prochain titre de même
niveau ou de niveau supérieur clôt la section. Les sous-titres ordinaires restent dans le
périmètre de l’article. Le contrôle porte sur la présence de code sous le titre. La part de
l’article formalisée et la correspondance de sens entre le texte et le code nécessitent une relecture.

Le relevé donne 273 identifiants LEGIARTI distincts, versions anciennes incluses.
Pour ★, le script retient la version en vigueur à la date de projection du code
(`articleInForce()`) et exige que le dernier rejeu terminé du dossier soit `passed` avec au moins
un test. Les 180 retraits ont le même motif dans le journal (`no_code`). Les liens du tableau pointent
vers les titres qui avaient servi à attribuer l’ancien marqueur.

Simulation en lecture seule, reproductible depuis la racine du dépôt.

```sh
DATABASE_URL='postgres://ubuntu@localhost:5432/bugdeloi?host=/var/run/postgresql' bun replications/c0.1/promote.ts --dry-run
```

Commande d’application après relecture. Elle met à jour l’index de couverture et les marqueurs
dans la même transaction. L’événement `reference.promoted` conserve le LEGIARTI, le motif et les
éléments de référence antérieurs de chaque retrait.

```sh
DATABASE_URL='postgres://ubuntu@localhost:5432/bugdeloi?host=/var/run/postgresql' bun replications/c0.1/promote.ts
```
